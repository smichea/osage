# Problem

During a fall, a camera may ask for a new façade while the capsule needs the floor below it. A slow texture or a second visit to the same street should consume little simulation time. Files on a server can arrive later than a tick even when the request began on time.

# Idea

Give the physics and visual selectors access to the same pool of content reads. Each file has a digest, a declared byte length and a distinct URL in the district. Match the response against its digest before publishing any decoded object.

# Method

The client fetches the index, coarse view and support catalogue for the initial scene. With an HTTP source, or a local directory opened with `--wall-clock`, the ordinary replay then advances against a wall clock. Local workers open the named files directly and verify their digests. Each lane can begin four requests. Four worker threads receive jobs from a queue of eight. If that queue fills, ordinary demand stays in its lane for the next tick. A second consumer of the same in-flight file receives the same ticket. A worker can skip a queued job once all interested callers have released it.

Workers read from the optional disk cache first. Every hit is checked. A missing or damaged chunk triggers an HTTP GET for that file. A verified response is written to a temporary file and renamed into place. When the index supplies an entity tag, the client saves both the index and the tag under a key derived from the district URL. A new process can use a conditional GET after checking the saved index digest. An unchanged index gives a 304 response and a changed index supplies the new body.[^http]

For the JSON directory the HTTP client accepts gzip or identity. The HTTP library enforces the read limit on the decoded representation. The client retains the verified decoded bytes and the validator that the origin supplied for the selected representation. Other files retain their explicit length and hash checks. The receipt's `index_body_bytes` counts decoded index data delivered on this visit. The independent HTTP oracle counts the bytes on the wire for both representations, checks a 304 second visit and retries a malformed gzip response. [Directory transport check](https://github.com/smichea/osage/blob/main/worlds/ville-paris/check-index-transfer.py).

A publisher can also supply a directory digest and encoded length with a world version. The cooker’s `--pin-index` option writes the immutable file before replacing `index.json`. Its eight-byte header stores the signature `ODI1` and the decoded JSON length as a little-endian u32. A single sized Zstandard frame or zlib stream follows. The native client checks encoded length and SHA-256, enforces a 64 MiB limit on each representation, and requires the whole stream to produce the declared length. The resulting JSON follows the ordinary district loader. A new world version can select a new digest while older clients continue to read their original directory. An offline restart needs the pin and every requested immutable file in cache.

For a PNG or JPEG, the worker also decodes the pixels and builds the mip levels before marking its ticket ready. The simulation publishes the completed image on a tick. For each independently addressed v4 model, a worker inflates the OMD1 payload and reads its glTF accessors into immutable arrays. Its ticket releases the compressed bytes and the intermediate GLB. The simulation checks the single identity placement, geometry-only shape, declared triangle and primitive counts, and texture-coordinate requirements before retaining a shared reference. It still reads each placement page, verifies its owner IDs and resource dependencies against the district index, and publishes the placements on a tick. A pending visual ticket keeps its previous representation on screen. For collision the verified support faces protect the landing until the full page is available. A failed demand read can be retried after one second. The all-resident control explicitly waits for its full batch. The default headless directory replay uses its deterministic link clock.

# Invariants

The origin receives requests for admitted content. The immutable disk cache holds only complete, digest-verified responses. Content IDs survive model placement and page changes. An HTTP or checksum error on a visual refinement preserves the resident parent. A slow full collision page uses the same owner and support coordinates as the resident control.

# Cost

Each cold chunk needs one response body and one digest check in the worker. A warm chunk uses a local file read and a digest check. The initial index can use one conditional round trip. The receipt counts requested objects and consumed body bytes separately from decoded content and GPU allocation. It excludes HTTP headers, TCP and TLS framing. The default remote replay uses actual arrival times. An explicitly requested artificial link profile adds a release deadline to the test.

On the 128 m Bir-Hakeim district with all geometry resident, a cold client requests 556 resources and receives 847,410 body bytes when it loads both graphics and physics. With `--no-visuals` it requests the common gzip directory (42,329 bytes), the support catalogue (18,356) and the 226 physical pages (19,777), totalling 80,462 bytes in 228 requests. Both clients receive a single 304 on a second run. On a plain origin serving the directory as identity, its 200,398 JSON bytes bring the physical total to 238,531. These counts exclude HTTP headers. On a warm local filesystem, complete district startup through tick zero with two collision queries took 671.6 ms of process CPU with graphics and 194.7 ms without graphics, as medians of seven alternating pairs on one logical core of an i5-1335U. This includes decoding, constructing the world and writing the receipt.

For the same 226 physical pages on a plain HTTP origin, the pinned directory takes 33,302 bytes. The complete cold physical transfer takes 71,435 body bytes in 228 requests. Distributing the textual pin separately costs another 70 ASCII bytes. A second process with a populated cache makes zero HTTP requests. A corrupted same-length directory entry costs one 33,302-byte repair request. All three delayed falls retain the same body samples, contact ticks and collision queries. [Immutable directory replay](https://github.com/smichea/osage/blob/main/worlds/ville-paris/check-pinned-directory.py)

Loading collision on demand changes the balance. With the same pinned 128 m district, the normal 64 m physics radius and a 1.4 s simulated delivery delay, the headless road and rail routes each fetched two physical pages (91 bytes). The roof route fetched three (213 bytes). The shared directory and support catalogue still cost 51,658 bytes at cold start. Each second launch on the same route used its cache for every read. The road capsule landed on certified support at tick 66, before its full page became available at tick 85. On the rail and roof the full landing page was ready thirteen ticks before first contact.

With `--support-region-tiles N`, the cooker also writes independently addressed support catalogues for groups of N × N tile keys. It separates a page whose actual horizontal span exceeds the group width. Each region binds its ordered tile coordinates and physical payload digests. The root assigns every physical tile to exactly one region. Each region remaps its certified face selections and omitted-triangle records to its local page order. On installation the reader checks these against the same source owners, bounds and full geometry as the whole catalogue.

Before starting the replay clock, the native client obtains every region needed by the spawn sweep. Later steps query the physical bounds hierarchy using the current body sweep, the individual moving parts and the capsule’s speculative contact envelope. On HTTP, the two-second trajectory forecast and in-flight physical detail pages feed up to four optional regional reads on the ordinary workers. Each wall-clock tick polls required tickets. Until validation, the directory bounds enclose every possible face of an unknown page. A nearby unknown page inside the conservative body, moving-part or start-of-step speculative envelope holds the actor at its current pose and velocity. A page touched only by the longer forecast can arrive later while the actor continues to move. A completed detail read keeps its ticket until the region validates or the lane loses interest. The lane reports this interval as `waiting_for_support`. The client retains installed regions for the session. A missing or invalid required region fails the replay. Whole-district residency, external observer tracks, moving bonnets and forecast impact audio use the complete catalogue.

A publisher may distribute the headless pin produced by `--pin-physics`. It carries the physical tile metadata, source ancestry and acoustic bindings. The cooker compares the complete compressed JSON (ODP1) and column (ODP2) files and publishes the shorter encoding. The column encoding requires every original coordinate to be exactly representable as binary32. The old pin still opens its original version. The client uses it with `--no-visuals --index-pin SHA256:BYTES`. The ordinary district remains available to rendering clients. [Regional reader and controls](https://github.com/smichea/osage/blob/main/worlds/ville-paris/check-support-regions.py)

ODP2 uses the same outer eight-byte header and bounded compression as ODP1. Its decoded payload starts with a little-endian u32 size and that many bytes of JSON. The JSON uses an empty digest field, the filename extension and zero bounds for the fields held in columns. Six consecutive planes contain little-endian binary32 values in physical row order, first the three lower coordinates and then the three upper ones. Each descriptor takes 32 binary digest bytes after the planes, in whole-support, regional-support and physical row order. The reader checks the exact column lengths, placeholder values and allowed extensions before restoring the native layer descriptors. The normal source-tree, extent, individual payload digest and catalogue binding checks still apply. [Native decoder](https://github.com/smichea/osage/blob/main/worlds/ville-paris/src/paging/tiles/directory_columns.rs)

The column pin for Bir-Hakeim occupies 14,739 bytes. Cold road and rail replays receive 15,870 HTTP body bytes each, and the roof receives 16,714. Every second run uses its disk cache for all files. All 1,843 body states and three first contacts match both the previous pin and the full-directory control. A sparse origin can supply the first road step with only the pin and the 675-byte spawn region (15,414 bytes). Withholding that region prevents the road replay from starting. At the rail and roof starting heights, the first step needs only the pin.

With `--pin-regional-physics`, an ODP3 root keeps the physical bounds, object tree, page sizes, filename extensions and ordered region membership. It addresses the global support file, each regional support file and one complete detail address table. Each regional file decompresses to the signature `ODR1`, one 32-byte SHA-256 digest per member in tile order, and the original support catalogue. The catalogue authenticates the association between those digests and tile coordinates. Fine geometry remains an independent resource. A page entering the physics lane can reuse an outstanding support read to discover its digest. A failed read for an optional address can retry after one second. A required collision read takes priority and checks the region before the threatened solver step. Installed addresses remain available for subsequent reads. [Native region reader](https://github.com/smichea/osage/blob/main/worlds/ville-paris/src/paging/support/regions.rs)

The client reads the complete detail address table for global support, unprotected playback, articulated bodies and moving supports. This preserves digest-based reservation events and whole-district certificate validation. Optional regional pins with wider source coordinates or an empty physical region set use the earlier lossless physics encoding. The public oracle checks every authored region against the ordinary directory, runs a sparse HTTP origin without the complete table, and exercises a lost optional response, a delayed landing and a corrupted address. [Regional address oracle](https://github.com/smichea/osage/blob/main/worlds/ville-paris/check-regional-addresses.py)

On the Bir-Hakeim fixture at 128 m per tile, a four-tile group gives a 5,908-byte root and 25 regions. The complete road and rail replays each receive 8,381 body bytes, the roof receives 8,506 and a lateral traversal receives 14,477. All four reproduce the fully resident body traces. A single-tile group spends more bytes on root addresses. Eight-tile groups bring more unrelated certificate and address data into the traversal, increasing its transfer to 21,775 bytes. The chosen width is configurable with `--support-region-tiles`.

With `--pin-bundled-physics`, each eligible regional descriptor can set `complete_pages`. Its decompressed ODR2 body begins with a four-byte magic and a 32-byte SHA-256 binding. For each tile, the binding hashes its two signed little-endian 32-bit coordinates followed by its lowercase ASCII page digest. The remaining bytes are the unmodified OCP1 pages in directory order. The root supplies each length and owner. The cooker measures both compressed representations and limits the full-page candidate to the existing uncompressed certificate length. Dense regions and legacy JSON pages can retain ODR1.

The reader verifies shapes, lengths, directory membership and the binding before enabling a region. It retains the decoded geometry in the regional catalogue and installs colliders only for active support or normal physics interest. A detail promotion can reuse an active native collider. The complete geometry is decoded on regional arrival and may cover considerably more triangles than the actor uses. Group width therefore also controls decoding work and memory. The all-resident mode still uses the district-wide address table and pages. For a rendered client, `--pin-visual-district` writes an ODI2 directory. Its bounded compression envelope is the same as ODI1. A little-endian u32 gives the length of a JSON header followed by exactly one 32-byte visual digest per tile, in tile order. The visual reader joins each digest to its validated extension. Physics rows retain their lengths, extensions, owners, bounds and materials. Their digests come from regional files or the signed global table. The reader validates visual descriptors, including empty visual rows within an object profile, before using them. A publisher can keep the old ODI1 index available, and both pins can refer to the same parent and fine meshes. The parent is the same 40,432-byte GLB envelope. At altitude the last format can render the first frame with those two files. Near the road the camera and actor can start with a further 529-byte support region. The public oracle removes other files, checks each bootstrap dependency, and compares the native GPU inputs, images, timed visual publications, source contact and body trace against both previous layouts. Its object fixture also checks near and forecast acoustic playback with JSON detail pages. A publisher that knows the client needs the first image can use `--pin-first-frame`. An ODI3 envelope decompresses to a twelve-byte header (inner directory version, little-endian directory length and region index), the directory, the parent, the legacy shared model library if present and any selected support file. The sentinel u32 maximum means no selected region. A district without physical regions includes its global support if present. Every member length and digest comes from the authenticated directory and is checked before use. A selected region enters the same validated support catalogue as a normal read. Only the actor's ordinary physics interests install colliders. The cooker and reader enforce a 64 MiB bound on both representations of the package.

For an OVC2 coarse parent, the producer compares two complete compressed launch files. One contains the original encoded parent. The other contains the same columns, tagged OVCU, with the existing intermediate, JSON and binary lengths, and no inner compression stream. The common outer frame can compress those columns together with the directory. This member needs no separate sidecar on the host. Both reconstruct the byte-identical GLB, including ordered placements and materials. Cold byte estimates charge the outer file once. [Coarse column semantics](/algorithms/coarse-district-storage.md)

[First-frame, warm cache and revision oracle](https://github.com/smichea/osage/blob/main/worlds/ville-paris/check-first-frame.py)

A first-frame update can use a previous decoded ODI3 payload as a Zstandard dictionary. The cooker's optional `--previous-first-frame` argument takes a previously published pin from the same output directory. It prints a launch reference with five SHA-256 and byte-length pairs separated by `~`. In order they identify the new full package, its decoded payload, the old full package, its decoded payload and the patch. The first pair is also an ordinary standalone pin. The publisher supplies the entire reference through the same trusted channel as an ordinary pin. Both the complete wire file and the decoded payload have independent identities.

With an empty cache the reader fetches and verifies the new full package and its decoded payload in one request. With the previous version in cache, it verifies either the old decoded file or the contents of the old wire file. It reads the patch, checks its digest, frame boundary and decoded length, and checks the result against the target payload digest. Success atomically stores the decoded result under its own `.frame` name. Another process can open that reference offline or use the decoded file as the base of a subsequent release. A plain wire pin still requires the wire file. An absent or damaged base goes straight to the full package. A failed update reads the complete current package and verifies both identities. The cooker returns the ordinary pin if it cannot produce a smaller transfer including the additional reference bytes.

Bir-Hakeim's metadata-only revision uses 199 HTTP body bytes against a 59,440-byte full package. The separate collision page traffic used to check the new surface is outside the launch transfer. The oracle compares the entire decoded package, native framebuffer inputs, first rendered image, and a complete segment query through the quay. It exercises a corrupt base, an unavailable or damaged patch, an authenticated invalid frame and an authenticated patch which reconstructs the wrong target. # Failure modes

Shared disk caches still need capacity planning. A live read can finish after its consumer departs. Geometry embedded in placement pages, material-specific alpha adjustment and GPU publication still cost time on the consuming thread. An image can remain on its parent representation for several ticks while a worker prepares it. A paced client in a district without a support catalogue can hold the actor until the full collision page is ready. A bootstrap origin failure can prevent a new session from starting.

# Alternatives

Archive ranges can combine nearby objects into one response. Their block alignment can also transfer bytes that the client never requests. Whole immutable files can be shared across different districts when their digests match.

# Reuse

Pass either a cooked directory or its HTTP(S) base URL to `ville-paris --paging --pages`. Supply a writable directory through `--content-cache` to reuse immutable files across processes. Any ordinary static HTTP host can serve the existing district files. [District paging](/algorithms/district-paging.md)
